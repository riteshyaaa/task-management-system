Design Notes

Partitioning. Both audit_log and user_activity_log are partitioned by created_at using PostgreSQL native range partitioning. Monthly partitions are recommended for the audit log; weekly or monthly for activity depending on volume. Old partitions can be detached and archived without affecting query performance.

Immutability. The audit_log and workflow_transition_history tables are append-only. Application-level enforcement is sufficient, though a BEFORE UPDATE trigger that raises an exception provides defense in depth.

Pre-aggregation. Velocity and performance metrics are materialized by background jobs, not computed on read. The computed_at column tracks freshness; the dashboard can show a "last updated" indicator and trigger a re-aggregation if stale.

Recurring task generation. A scheduler polls recurrence_rules where status = 'ACTIVE' AND next_occurrence <= now(). It checks for exception dates, generates the task instance, increments occurrences_created, and computes the next occurrence. If max_occurrences is reached or end_date is past, status moves to COMPLETED.

Workflow versioning. When a workflow structure changes, version is incremented and the old definition archived. Existing tasks continue on their assigned workflow version; only new tasks pick up the latest. The denormalized state names in workflow_transition_history ensure historical readability.

Assumed base tables. This schema references users, tasks, and projects as existing tables with UUID primary keys. All timestamps use TIMESTAMPTZ (UTC storage with timezone awareness).
